Using SQL Workspace

Explore the database

Expand a table to see its columns and data types. Select Preview to see its records below the editor. Previewing a table does not replace your SQL.

Run your SQL

Select Run, or press Ctrl + Enter (Cmd + Enter on Mac) or Shift + Enter. Highlight part of your SQL to run only that selection. Separate multiple statements with semicolons; each statement gets its own results tab. Large results show the total number of rows returned and a limited preview.

Complete a word or name

Press Ctrl + Space or select Complete for matching SQLite keywords, tables, views, and columns. Use the arrow keys and Enter or Tab to insert a suggestion; Escape closes the list. Completion changes only the current word, after you choose a suggestion. It is unavailable inside text values or comments.

Typing a table’s name and a period narrows the list to that table’s columns. For other prefixes, such as an alias, the list shows matching columns from the database; it does not analyze aliases, joins, or common table expressions. The source table is shown beside each column.

Copy to and from Canvas

Copy SQL copies the highlighted selection, or all your SQL if nothing is selected, as plain text. Paste it into your Canvas answer. You can paste SQL back into this editor. Clipboard access still depends on Canvas and your exam browser settings; this workspace does not bypass those restrictions.

Clean pasted text

The editor checks pasted SQL for unusual spaces, invisible formatting characters, and curly quotation marks. Cleanup preserves characters inside existing quoted values and comments. A notification identifies changes and offers Undo cleanup. Clean text checks the full editor; Run also checks before executing. Review quoted values yourself if they contain unwanted characters.

Understand errors

After Run, SQLite’s original error appears beside the failed statement in the editor and in the results panel. The marker identifies the start of the failed statement, not necessarily the exact character causing the error. Inline markers clear when you edit the SQL. There is no separate background syntax checker and no added explanation or suggested correction.

Execution stops at the first error. Earlier successful statements remain applied, and their result tabs remain available.

Reset, stop, and save

Reset database restores the original data while keeping your SQL. Stopping a long query, or reaching its time limit, also resets the database. Changes to the database stay in this browser tab’s memory. Refreshing the page removes created views and other database changes.

Practice and test drafts are separate. Your SQL draft is restored after refreshing this tab within the same practice or test session when browser storage is available. Each new test starts with its own draft. It is not a submitted answer or a backup. Copy your final SQL into Canvas as instructed.
